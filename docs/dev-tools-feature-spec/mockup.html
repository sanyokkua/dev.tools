Dev Environment Setup

How to read this mockup

Purpose. This file is the visual source of truth for two features: the new Dev Environment Setup page and the updated Software Installer page. It is built with the app's real CSS custom-property tokens (copied verbatim from src/styles/colors.scss) and the app's real component class names (.steplabel, .chip/.chip.on, .pill, .card.pad, .code-block, a simplified .segctrl standing in for the real SegmentedControl React component) so an implementer can map every region directly back to the real source files described in the specification.

Color tokens used above

Toggle the theme button in the toolbar to see the full light/dark token swap — every color in both page mockups comes from a CSS variable, never a hardcoded hex value, matching the project's own rule ("use CSS custom properties, not hardcoded hex values").
--primary --primary-container --secondary-container --tertiary-container --success-container --warning-container --error-container --info-container --card --card-2 --code-bg

Widget-to-component mapping

  • .segctrl in this mockup stands in for the real SegmentedControl component (src/components/controls/SegmentedControl.tsx) — used for Category, OS, Action, Scope, and Update-scope pickers.
  • .chip / .chip.on / .chip.disabled are the real classes from chip.scss, used for multi-select package-manager pickers in both features.
  • .steplabel / .step-row-num is the real numbered-circle step header pattern from primitives.scss, used identically on both pages for "Step 1 / Step 2 / …" groupings, matching BrewInstallSteps.tsx's existing convention.
  • .code-block stands in for the real CodeSnippet component (src/components/elements/CodeSnippet.tsx) — traffic-light dots, header title, Copy button (wired to copyToClipboard() + a toast), and an optional Download button.
  • .pill.warn is used for the new "requires repo" badge (Feature A) and for caveat badges (Feature B); .pill.muted is used for informational counts in the summary bar.
  • .tool-about stands in for the real ToolAbout component — collapsible description box shown at the top of every tool page.

Responsiveness

Use the Viewport buttons above (375 / 768 / 1280 / Full) to preview how both pages reflow — this mirrors the project's own automated check (24+ routes × 3 widths × 2 themes, zero tolerance for horizontal overflow or a collapsed Monaco editor). Concretely in this mockup: the two-column basket/output layout (.grid-2) collapses to one column under 860px; the sidebar hides entirely under 480px, matching how the real app's mobile layout already behaves; chip rows wrap naturally via flex-wrap rather than overflowing horizontally, since horizontal overflow is an automatic failure in this project's build gate.

Edge cases demonstrated in the two page mockups above

  • Unavailable manager, omitted: on the Dev Environment Setup page, switching Category to Java and OS to Windows does not show a jenv chip at all (it doesn't exist for that platform) — only managers that are genuinely applicable are offered.
  • Available-with-caveat, shown with explanation: selecting Node.js → Windows → "nvm" on the Dev Environment Setup mockup shows an inline warning note explaining it's an unrelated project from Unix nvm, rather than silently giving wrong-context instructions.
  • Repo-required badge (Feature A): the Software Installer mockup's app basket shows a requires repo requires repo pill next to Temurin, and the generated script view shows the deduplicated ### Repository setup (one-time) block before ### Install.
  • "Everything this manager manages" toggle (Feature A): shown in the Output step's Update-scope control; when active, the per-app override controls in the basket are visibly dimmed (.override-dim) rather than hidden, with a caption explaining why.
  • System-wide maintenance scope (Feature A): a third Scope option that requires only a manager selection, no apps — shown with its own empty state when no manager is picked yet.
  • Empty states: both pages show a dashed-border .empty-state block with explanatory copy rather than a blank area, matching the existing "Select at least one app…" pattern already in ScriptOutput.tsx.
